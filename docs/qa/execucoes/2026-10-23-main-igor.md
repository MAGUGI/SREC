* A stack compartilhada que estava no ar em `39237e3` (`srec-run`, com o
  `docker-compose.override.yml`) **não aplicava migrations**: o comando de dev era
  `npm run dev`, o schema saía do `initDb.js`, e a tabela `reservations` tinha
  `timestamp without time zone` e nenhuma das constraints de exclusão, janela e
  status. Corrigido por OPS-02 (#54), que pôs `npm run db:migrate` antes do
  `npm run dev`. Quem tiver a stack de antes de `a86cab5` precisa recriar o
  volume ou subir de novo para receber as migrations.
* A API tem limite de 20 escritas por minuto (`RateLimit-Policy: 20;w=60`).
  Executar o bloco C por `curl` em sequência rápida pode esbarrar em `429`.

## Bugs novos encontrados

### N2-QA-01 — POST e PATCH sem `Content-Type: application/json` devolvem 500

* **Severidade:** MÉDIO
* **Onde:** `server/src/controllers/reservationController.js:7` e `:16`; `POST /api/resources` também
* **Encontrado em:** passos C-03, C-04 e C-10 do roteiro de regressão
* **Commit:** `d5d56ef`
* **Ambiente:** curl 8 (git-bash, Windows 11) · America/Sao_Paulo · Postgres `UTC`
* **Origem:** herdado (o `express.json()` só popula `req.body` com o cabeçalho certo; os controllers desestruturam `req.body` sem checar)

**Passos para reproduzir**

1. `curl -i -X POST http://localhost:5000/api/reservations -d '{"resource_id":1,"user_name":"t","start_time":"2026-11-10T11:00:00Z","end_time":"2026-11-10T09:00:00Z"}'`
2. `curl -i -X PATCH http://localhost:5000/api/reservations/1/status -d '{"status":"banana"}'`
3. `curl -i -X POST http://localhost:5000/api/resources -d '{"name":"X","type":"workstation","capacity":-5}'`

**Resultado esperado**

`400` (ou `415`) explicando que o corpo precisa ser JSON — o contrato de erro do
ADR-06 reserva `500` para falha não prevista do servidor, não para requisição
malformada do cliente.

**Resultado obtido**

`500 {"error":"Erro interno do servidor.","code":"INTERNAL_ERROR"}` nos três. Log
do server: `TypeError: Cannot read properties of undefined (reading 'resource_id')`
em `reservationController.js:7:28`, e `(reading 'status')` em
`reservationController.js:16:135`. `PUT /api/resources/1` sem cabeçalho responde
certo: `400 EMPTY_UPDATE`.

**Impacto**

O frontend sempre manda o cabeçalho, então o usuário da tela não é afetado. Um
cliente de API que esqueça o cabeçalho recebe erro de servidor em vez de erro de
validação, e o log registra `level: error` com stack trace para um erro do cliente.

**Evidência**

Saída de `curl -i` e do `docker compose logs server` reproduzida acima.
